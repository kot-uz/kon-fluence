# Документация (kon-fluence)

Приложение документации: дерево страниц,
редактор на TipTap, вложения, черновики, разрешение конфликтов версий.

## Запуск

```bash
npm install
npm run dev      # http://localhost:3010
npm run build    # сборка в ./build
npm run preview  # просмотр собранной версии
npm run lint
npm run typecheck # проверка типов TypeScript
```

По умолчанию данные хранятся на устройстве (режим `local`): они лежат в IndexedDB браузера, бекенд не нужен.
При первом открытии пространство наполняется демо-страницами.

## Режимы хранения

| Режим                       | Где лежат данные                | Нужен ли аккаунт |
| --------------------------- | ------------------------------- | ---------------- |
| `local` («На этом устройстве») | IndexedDB браузера, режим по умолчанию | нет              |
| `cloud` («В облаке»)           | PostgreSQL и S3 на сервере      | да               |

Режим выбирается в шапке и запоминается в `localStorage['docs-storage-mode']`. Облачный режим виден,
только если задан `REACT_APP_API_URL`. После входа в аккаунт приложение предлагает перенести
данные с устройства в облако; локальная копия при этом не удаляется, её можно очистить в меню
(«Очистить данные на устройстве»). Обратного переноса из облака на устройство нет.

## Бекенд

Каталог `server/`: Fastify + TypeScript, PostgreSQL 16, S3 (MinIO локально), Drizzle ORM.
Общие типы и утилиты фронтенда и бекенда — в `shared/` (npm workspaces).

### Локальный запуск

```bash
npm install
cp server/.env.example server/.env          # для запуска вне Docker
docker compose up -d postgres minio minio-init
npm run db:migrate --workspace server       # применить миграции
npm run dev --workspace server              # http://localhost:3000, проверка: GET /health
```

Затем во фронтенде в `.env`: `REACT_APP_API_URL=http://localhost:3010` и `npm run dev`
(Vite проксирует `/docs` и `/auth` на бекенд).

Всё вместе в Docker (миграции применяются при старте контейнера):

```bash
JWT_SECRET=<не короче 32 символов> docker compose up --build
```

### Переменные окружения сервера

| Переменная                              | Назначение                                              |
| --------------------------------------- | ------------------------------------------------------- |
| `DATABASE_URL`                          | строка подключения к PostgreSQL                         |
| `JWT_SECRET`                            | секрет подписи токенов, не короче 32 символов           |
| `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET` | S3-совместимое хранилище вложений                       |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY`        | ключи доступа к хранилищу                               |
| `PORT`, `HOST`, `LOG_LEVEL`, `NODE_ENV` | параметры запуска                                       |
| `AUTH_RATE_LIMIT_MAX`                   | запросов в минуту на register/login/refresh с одного IP |

### Возможности

- Авторизация: access-JWT на 15 минут и refresh-токен на 30 дней в httpOnly-cookie с ротацией.
- Участники пространства: владелец добавляет пользователей по email с ролью «редактор» или «читатель»
  (`/docs/Spaces/{id}/Members`); в интерфейсе — пункт «Участники» в меню пространства.
- Вложения до 100 МБ, скачивание с `Range`. Видео и аудио играют по подписанной ссылке
  (`POST /docs/Attachments/{id}/SignedUrl`, действует 1 час), изображения загружаются как Blob.
- Раз в час сервер удаляет просроченные сессии импорта и вложения старше суток, на которые не ссылается ни одна страница.

### Тесты и миграции

```bash
npm test --workspace server                  # Vitest + Testcontainers, нужен запущенный Docker
npm run typecheck                            # фронтенд, shared и сервер
npm run db:generate --workspace server       # новая миграция после изменения server/src/db/schema.ts
```

Миграции из `server/drizzle/` коммитятся в репозиторий. CI (`.github/workflows/ci.yml`) прогоняет
линтер, проверку типов, сборку, тесты, применение миграций на чистой базе (и проверяет, что схема
в коде не расходится с миграциями) и сборку Docker-образа сервера.

## Маршруты

| Путь                                | Страница                                              |
| ----------------------------------- | ----------------------------------------------------- |
| `/`                                 | список пространств                                    |
| `/docs/space/:spaceId`              | документация пространства (откроется первая страница) |
| `/docs/space/:spaceId/:pageId`      | просмотр страницы                                     |
| `/docs/space/:spaceId/:pageId/edit` | редактирование страницы                               |

## Пространства

Пространства самостоятельные: список и страницы хранятся вместе — в IndexedDB (режим `local`)
или в бекенде (режим `cloud`). Список приходит из `GET /docs/Spaces`. Создание, переименование и
удаление — на главной странице. Удаление пространства удаляет и его страницы с вложениями.

Полностью очистить локальные данные можно кнопкой «Сбросить демо-данные» в диалоге
автора правок (иконка пользователя в шапке).

## Переключение на реальный бекенд

```dotenv
REACT_APP_API_URL=https://api.example.com
```

Режим хранения (`local` / `cloud`) выбирается в рантайме и хранится в `localStorage['docs-storage-mode']`.
Если `REACT_APP_API_URL` пустой, облачный режим скрыт.

Приложение будет обращаться к `/docs/Spaces/...`, `/docs/Pages/...`, `/docs/Attachments/...`
(контракт описан в `src/app/docs/local/handlers.ts`). Токен берётся из `localStorage`,
ключ `jwt_access_token`. Вход и регистрация — на `/login` и `/register`, при 401 токен
обновляется через `/auth/refresh`.

В dev-режиме запросы `/docs` и `/auth` проксирует Vite на `DEV_API_PROXY_TARGET`
(по умолчанию `http://localhost:3000`), поэтому `REACT_APP_API_URL` указывает на сам dev-сервер
(например, `http://localhost:3010`) — refresh-cookie остаётся на одном origin.

Переменные используют префикс `REACT_APP_`, хотя сборщик — Vite: подстановку
`process.env.REACT_APP_*` делает `define` в `vite.config.ts`.

## Автор правок

В режиме `local` имя автора задаётся локально (иконка пользователя в шапке) и хранится
в `localStorage`. В режиме `cloud` автор берётся из аккаунта. Имя подставляется в «Создал(а)» и «Обновлено».
